## 1. 验收范围

### 1.1 覆盖范围

| 范围 | 验收形式 |
|---|---|
| 7 大需求点的端到端可玩闭环 | 自动化集成测试 + 真机抽样 |
| Android 构建产物（apk/aab）可在小米17 Ultra 安装运行 | 用户配合 |
| MIDI 文件解析正确性 | 自动化单元测试 + fixture 比对 |
| DK 谱 JSON 序列化反序列化兼容性 | 自动化单元测试 |
| 学习模式 / 演奏模式判定逻辑 | 自动化集成测试（DebugMidiInjector 注入伪 MIDI） + 真机抽样 |
| 统计准确性 | 自动化测试 |
| 设置项持久化 | 自动化测试 + 手动抽查 |
| 谱面库导入导出 | 用户配合 |
| 屏幕方向、视口、横屏锁定 | 真机视觉验收 |
| 跨平台架构预留 | 静态代码检查（领域层无平台依赖） |

### 1.2 不覆盖

| 项 | 原因 |
|---|---|
| iOS / Windows 构建 | v1.0.0 Out of Scope |
| 蓝牙 MIDI 接入 | v1.0.0 Out of Scope |
| 手位识别准确率 | v1.1.0 才加 |
| 长按时长判定 | v1.1.0 才加 |
| 网络功能 | v1.0.0 无网络 |
| 性能压测（极端 1000+ note/秒 MIDI） | v1.0.0 仅要求常规曲目 60fps |
| 不同型号电钢琴兼容性 | v1.0.0 仅在用户提供的电钢琴上抽样验收 |

### 2.3 测试数据

`test_fixtures/` 目录下需包含至少以下文件，由 Stage 3/7 准备：

| 文件 | 用途 |
|---|---|
| `simple_format0_8bars.mid` | SMF 格式 0，8 小节 C 大调音阶 |
| `simple_format1_2tracks.mid` | SMF 格式 1，2 轨（右手旋律 + 左手伴奏） |
| `tempo_change.mid` | 含 tempo change 事件 |
| `time_signature_3_4.mid` | 拍号 3/4 |
| `corrupted.mid` | 故意损坏的 MIDI 文件（用于触发 CorruptedMidiException） |
| `format2.mid` | SMF 格式 2（用于触发 UnsupportedMidiFormatException） |
| `golden_simple_format0_8bars.dk.json` | 上述 simple_format0_8bars.mid 转换后的预期 DK 谱（gold standard） |

## 4. 验收项

### V1. 跨平台架构强约束自检（自动化）

- **目的**：验证领域层无平台依赖，保证未来 iOS/Windows 移植无阻塞。
- **前置条件**：已检出仓库 main 分支。
- **操作步骤**：
  1. 在仓库根目录执行 `bash scripts/check_layering.sh`（由 Stage 2 提供该脚本）
  2. 脚本会 grep `app/lib/domain/` 下所有 dart 文件的 import 语句，匹配以下黑名单字符串之一即报错：
     - `package:flutter/`
     - `package:flutter_riverpod/`
     - `dart:ui`
     - `dart:html`
     - `dart:js`
     - `package:keydrop_piano/platform/`
- **期望结果**：脚本退出码 0，输出 "Layering check passed."
- **通过标准**：退出码 = 0
- **失败标准**：退出码 != 0，输出含违例的文件名 + 行号
- **证据要求**：保留脚本完整 stdout + stderr 到 `Document/Update/v1.0.0 - 初始可玩版本/验收证据/V1.log`

### V3. 端到端集成测试通过（自动化，伪 MIDI）

- **目的**：在没有真实电钢琴的环境下验证端到端流程。
- **前置条件**：
  - 已连接一台 Android 设备或启动 Android 模拟器
  - 模拟器/设备已安装 debug 构建（包含 `DebugMidiInjector`）
- **操作步骤**：在 `app/` 目录执行 `flutter test integration_test/`
- **期望测试场景**（每个必须有独立 test case，全部 PASS）：
  - 场景 A：导入 `simple_format0_8bars.mid` → 生成 DK 谱 → 与 `golden_simple_format0_8bars.dk.json` byte-equal（忽略空白）
  - 场景 B：加载上述 DK 谱 → 演奏模式 → DebugMidiInjector 按 ±15ms 内的时间精确注入所有 note → 期望统计：完美 = note 总数，掉 key = 0，错音 = 0
  - 场景 C：加载上述 DK 谱 → 学习模式 → DebugMidiInjector 第 3 个 note 故意按错音 1 次再按对 → 期望：错音统计 = 1，整体仍可继续到第 4 个 note
  - 场景 D：尝试导入 `format2.mid` → 期望抛 `UnsupportedMidiFormatException` 且 UI 弹窗显示对应 message
  - 场景 E：BPM 倍率设为 2.0 → 加载 DK 谱演奏 → 实际事件时间线 = 原 t × 0.5（误差 ≤ 1ms）
- **通过标准**：所有场景 PASS
- **失败标准**：任一场景 FAIL
- **证据要求**：完整 test 输出保存到 `验收证据/V3.log`

### V5. 真机：APK 安装与首次启动【需用户配合】

- **目的**：验证 release 构建可在目标机型正常安装运行。

- **操作步骤**：
  1. `adb install -r app/build/app/outputs/flutter-apk/app-release.apk`

  3. 观察首次启动行为
- **期望结果**：
  - 安装无错误
  - App 启动后强制横屏
  - 默认进入谱面库页（首次启动谱面库为空 + 提示"导入 MIDI 创建谱面"）
  - 屏幕常亮（验收时长 > 30 秒，屏幕未自动息屏）
- **通过标准**：以上 4 条全部满足
- **失败标准**：安装失败 / 启动崩溃 / 未横屏 / 30 秒内息屏
- **证据要求**：手机截图 1 张（启动页）+ 用户文字描述

### V6. 真机：MIDI 文件导入与谱面生成【需用户配合】

- **目的**：验证端到端读谱功能。
- **前置条件**：
  - 用户已将 `simple_format0_8bars.mid` 通过任意方式（USB / 微信 / 邮件）放到手机本地存储
- **操作步骤**：
  1. 在 App 谱面库页点击右下角"+"按钮
  2. 进入谱面转换页 → 点击"选择 MIDI 文件"
  3. 通过 SAF 选择 `simple_format0_8bars.mid`
  4. 选择旋律轨（应只有一轨可选）
  5. 点击"生成 DK 谱"
  6. 输入名称"测试谱 1"，保存
  7. 返回谱面库页
- **期望结果**：
  - 谱面转换页显示曲名、BPM、拍号、调号等元信息
  - 保存后谱面库列表出现"测试谱 1"项
- **通过标准**：以上 2 条全部满足
- **失败标准**：任意步骤出错或弹窗报错
- **证据要求**：3 张截图（转换页、保存对话框、谱面库列表）+ 用户文字描述

### V7. 真机：电钢琴连接与学习模式【需用户配合】

- **目的**：验证 USB OTG MIDI 实时输入 + 学习模式核心闭环。
- **前置条件**：
  - 用户已准备一台 USB Class Compliant 电钢琴
  - OTG 线缆就位
  - 手机 OTG 已开启
  - V6 已通过
- **操作步骤**：
  1. 用 OTG 线连接电钢琴 USB-B 与手机 USB-C
  2. 在 App 谱面库点击"测试谱 1" → 选择"学习模式" → 进入播放器页
  3. 观察播放器顶部"设备状态"显示
  4. 当首个 key 落到判定线后停止下落，用户按下对应电钢琴键
  5. 持续按完整 8 小节
- **期望结果**：
  - 步骤 3：显示电钢琴设备名称（如 "USB-MIDI" / "Yamaha P-XXX"）
  - 步骤 4：按下后 key 消失，下一 key 开始下落
  - 错按一个其他键：屏幕短暂闪红边框 + 该键位高亮红色 0.5s
  - 8 小节完成后跳转到完成页，统计区显示"完美/抢拍/拖拍/掉 key/错音"各项数字
- **通过标准**：以上 4 条全部满足
- **失败标准**：设备不识别 / key 不响应 / 错按无反馈 / 完成无统计
- **证据要求**：屏幕录像 1 段（≥ 30 秒，覆盖至少 4 个 key）+ 用户文字描述

### V10. BPM 倍率调节真机验证【需用户配合】

- **目的**：验证 BPM 倍率影响时间线。
- **前置条件**：V8 已通过。
- **操作步骤**：
  1. 进入设置页 → BPM 倍率改为 0.5x
  2. 演奏"测试谱 1"
  3. 比较演奏总时长与 1.0x 时的差异
  4. 再改为 1.5x 重复
- **期望结果**：
  - 0.5x 时演奏总时长 ≈ 2 × 1.0x 时长（±5%）
  - 1.5x 时演奏总时长 ≈ 0.667 × 1.0x 时长（±5%）
  - 信息栏显示当前 BPM = 原 BPM × 倍率
- **通过标准**：3 条全部满足
- **失败标准**：时长偏差超过 5% / 信息栏不更新
- **证据要求**：3 段录屏（0.5x / 1.0x / 1.5x）总时长记录表 + 用户文字描述

## 5. 失败与阻塞处理

| 场景 | 处理 |
|---|---|
| V1-V4 自动化失败 | 必定回退到对应 Stage 修复，禁止豁免 |
| V5-V10 真机失败 | 先检查是否为环境问题（OTG 未开、电钢琴特殊驱动等），排除后回退 Stage 6 / Stage 4 修复 |
| V11 文档缺失 | 回退到对应 Stage 补充文档，禁止"事后补"的形式占位 |
| 用户因硬件不可得无法配合 V5-V10 | 标记为"阻塞"，记录原因，**不得标记通过**。MainAgent 需追加问题清单决定是否豁免（豁免需用户书面确认） |
| 验收文档本身有歧义 | 必须先修订本文档，重新自检 6.3 标准，再继续验收 |
