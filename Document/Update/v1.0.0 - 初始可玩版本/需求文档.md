# v1.0.0需求

我接下来要做的一个软件，其目标平台是安卓手机/IOS手机/Windows电脑，当前项目名称为KeyDrop_Piano，键落钢琴，其主要目的是为了简化用户学习钢琴的过程，不需要学习复杂的乐理知识，只需要学会如何先上车，后补票。

技术栈的选型的话，我觉得可能还是通过前台、后台的形式来做会合适一点，这样也适合跨平台和套皮，只是说可能在不同的平台上它的技术栈可能有些不一样，这个地方可能需要一些讨论，但是尽量按照这个思路去设计。

一般的电钢琴，都会有一个专门的midi接口，手机可以直接连接到这个midi口，然后手机就可以获得这个midi的演奏实时情况，现在我想要做的事情是，将一个钢琴谱或者midi谱扫描后，生成一种特定的下落式钢琴谱文件，然后在界面上下落。界面上最下方是一排琴键，琴键和现实中的琴键是一一对应的，当下落的key落到琴键上的时候，用户只需要按一下对应琴键上的键，这样就可以进入下一个key，否则就卡在当前的key位置上。

就像音游一样游玩就可以了，用户需要做的就是按照琴谱的引导，完成这个乐曲的演奏，这里可能需要考虑到按键的时长、多个键位的组合，和弦，手指位置等。

## 具体需求：

0. 可能需要你调研一下电钢琴转OTG -> 手机typeC的这个数据流路线。

1. 需要你首先设计一个这样的可以跨平台使用的结构，当然了我对这种跨安卓、苹果、windows的不太了解，你可以给我几个选择，或者实在是不好做的话，也可以直接分版本做。但是无论如何，目前着重做安卓版本的。

2. 需要你做一个读谱功能，就是直接用户上传对应的midi谱，然后生成一个下落key的谱。

3. 需要你做好这个界面的原型设计，在正式开始工作之前，请你将这个原型设计好，我确认好原型之后再来说如何进行下一步开发。界面上应该要显示BPM，拍号等midi中的信息。钢琴键位的摆放（钢琴键位需要用户去设计一下，多少键位）方式，界面显示（需要注意，这是一个普通的安卓手机，请你在原型中展示这一点）设置界面，铺面转换，以转换的铺面文件检索等功能都需要逻辑清晰的展示出来。

4. 需要你做好key-drop的显示，动画特效，以及用户按照正确的节拍按键以及强拍或者拖拍的统计工作，都需要做一下，以及生成给出不同的动画效果（不是说在屏幕中间显示，就是在key被按下的那个时候的显示，当然了，用户应该不会错过这个key，如果遇到了没有动，那么就会卡在这个key这里）。

5. 需要提供两种模式，一种是需要用户正确去按的学习模式，学习模式下，key会等用户，直到用户按到了key，才会进行到下一阶段。如果用户没有按到key，那么就会一直等待，这个时候演奏的声音也是用户弹奏的实际的midi的声音。如果是演奏模式，那么key就不会等用户，而是按照midi的规定一直这么演奏下去，但是这个时候仍然需要统计用户抢拍、拖拍、掉key的情况。

6. 允许用户设置bpm，修改了bpm之后会对应的影响演奏的快慢，包括key的快慢。

7. 允许导入、导出 drop-key谱，这里之后就叫DK谱就行。
