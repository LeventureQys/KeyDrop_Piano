## 1. 目标与背景

### 1.1 目标（1 句话）
在领域层实现 **SMF（Standard MIDI File）解析器** `MidiParser`（支持格式 0/1，识别 Note/Tempo/TimeSig/KeySig/EndOfTrack/延音CC）与 **DK 谱生成器** `DkGenerator`（多轨合并、去重、可选旋律轨），把 `Uint8List` MIDI 字节转换为 Stage 2 的 `DkScore`；并提供完善单元测试。

### 1.2 关键设计原则（强制）
- **领域层零平台依赖**：`MidiParser` / `DkGenerator` 只接收 `Uint8List`（或 `List<int>`）字节，**不接触文件路径、不 import `dart:io`**。文件→字节的读取属平台层（Stage 4）。
- 时间一律毫秒整数（Version D1）。
- 不支持格式（格式 2、SMPTE division、SysEx-only 等）→ 抛 `UnsupportedMidiFormatException`；字节结构损坏 → 抛 `CorruptedMidiException`（均来自 Stage 2 异常体系）。

## 3. 中间数据模型（SubStage 3.1，`lib/domain/models/midi_data.dart`）

`MidiParser` 输出的中间结构（领域内部用，不直接序列化）：

```dart
enum MidiFormat { single, multiTrack } // 格式0=single, 格式1=multiTrack（格式2 直接抛异常，不入枚举）

@immutable
class MidiData {
  final MidiFormat format;
  final int ticksPerQuarter;          // division（metrical），> 0
  final List<MidiNoteEvent> notes;    // 已合并所有轨道、已转换为毫秒、按 startMs 升序
  final List<MidiTempoChange> tempoMap; // 至少含 t=0 的初始 tempo（无显式 tempo 时默认 120bpm）
  final String timeSignature;         // "4/4"（无则默认 "4/4"）
  final String keySignature;          // "C"（无则默认 "C"）
  final int totalDurationMs;          // 最后一个 note 的 (startMs + durationMs) 最大值
  final List<MidiTrackInfo> tracks;   // 每个原始轨道的统计（供转换页选旋律轨）
}

@immutable
class MidiNoteEvent {
  final int trackIndex;   // 来源原始轨道号（格式0 全为 0）
  final int channel;      // 0-15
  final int startMs;
  final int durationMs;   // noteOn 到匹配 noteOff（或同pitch noteOn velocity0）的时长；未配对则到曲尾
  final int pitch;        // 0-127
  final int velocity;     // 1-127（noteOn）
}

@immutable
class MidiTempoChange { final int t; final double bpm; }  // t 毫秒

@immutable
class MidiTrackInfo {
  final int trackIndex;
  final int channel;        // 该轨主通道（首个 note 的 channel；无 note 则 -1）
  final int noteCount;
  final int minPitch;       // 无 note 时 -1
  final int maxPitch;       // 无 note 时 -1
  final String? trackName;  // 来自 FF 03 Track Name meta（可空）
}
```

## 4. SubStage 3.1 任务书 - SMF 解析器

### 4.1 SMF 二进制规范要点（解析器必须正确处理）
- **Header chunk**：ASCII `"MThd"` + 4字节长度(=6) + `format`(2B) + `ntrks`(2B) + `division`(2B)，全部大端。
  - `format == 2` → 抛 `UnsupportedMidiFormatException("SMF 格式 2 不受支持，v1.0.0 仅支持格式 0/1")`。
  - `division` 最高位为 1（SMPTE 帧率）→ 抛 `UnsupportedMidiFormatException("不支持 SMPTE 时基")`；否则 `ticksPerQuarter = division & 0x7FFF`，必须 > 0，否则 `CorruptedMidiException`。
  - `"MThd"` 不匹配或长度字段 ≠ 6 → `CorruptedMidiException`。
- **Track chunk**：ASCII `"MTrk"` + 4字节长度 + 事件流。chunk 长度越界/不足 → `CorruptedMidiException`。
- **Delta-time**：可变长度量（VLQ），每字节低 7 位有效，最高位为延续标志。
- **事件**（含 running status：状态字节缺省时复用上一个 MIDI 状态字节）：
  - `0x8n` Note Off：pitch、velocity。
  - `0x9n` Note On：velocity==0 视为对应 pitch 的 Note Off。
  - `0xAn`(aftertouch)/`0xBn`(CC)/`0xEn`(pitchbend)：各 2 数据字节；`0xCn`/`0xDn`：1 数据字节。CC 64(延音)记录但 v1.0.0 不参与判定。
  - `0xFF` Meta：`FF 51 03 tttttt`=Tempo（微秒/四分音符）；`FF 58 04 ...`=TimeSig；`FF 59 02 ...`=KeySig；`FF 03 len ...`=Track Name；`FF 2F 00`=End of Track；其余 meta 按 len 跳过。
  - `0xF0`/`0xF7` SysEx：按 VLQ 长度跳过（不参与 DK 谱）。
- **tick → ms 转换**：按 tempoMap 分段累计。`ms(tickN) = Σ 各段 (段tick数 * (60000 / bpm / ticksPerQuarter))`，四舍五入为整数毫秒。

### 4.2 接口
```dart
class MidiParser {
  /// 解析 SMF 字节为中间模型。失败抛 DkException 子类。
  MidiData parse(Uint8List bytes);
}
```
- 解析时为每个轨道独立维护 running status；多轨（格式1）各轨从 t=0 起算 tick，转换 ms 时使用全局 tempoMap（格式1 的 tempo 通常在第 1 轨；解析时先扫描所有轨收集 tempo 形成全局 tempoMap，再统一换算）。
- noteOn/noteOff 配对：同 (channel,pitch) 用栈/队列匹配最近未闭合的 noteOn；曲尾仍未闭合的 note，duration = totalTick 末尾 - startTick。
- 默认值：无 tempo → tempoMap=[{t:0,bpm:120}]；无 timeSig → "4/4"；无 keySig → "C"。

### 4.3 KeySig 解码
`FF 59 02 sf mi`：`sf`(有符号，-7..+7 升降号数)、`mi`(0=大调,1=小调)。映射到调名字符串（大调圈：0=C,1=G,...,-1=F,...；小调加 "m"，如 "Am"）。无法识别时回退 "C"。

### 4.4 测试 fixture（`tool/gen_midi_fixtures.dart` 生成到 `test/fixtures/`）
脚本用纯 Dart 写出合法 SMF 字节，生成至少 5 个文件：
1. `f0_cmajor_scale.mid`：格式0，单轨，C大调音阶 8 个 note，120bpm，4/4。
2. `f1_two_tracks.mid`：格式1，2 轨（旋律 + 低音），含 Track Name meta。
3. `f1_tempo_change.mid`：格式1，曲中 tempo 由 120→90。
4. `f1_timesig_keysig.mid`：格式1，3/4 拍、G 大调（sf=1）。
5. `format2.mid`：格式2 header（用于触发 UnsupportedMidiFormatException）。
6. `corrupted.mid`：MThd 头损坏（用于触发 CorruptedMidiException）。

## 5. SubStage 3.2 任务书 - DK 谱生成器

### 5.1 接口
```dart
class DkGenerator {
  /// 由 MidiData 生成 DkScore。
  /// [melodyTrackIndex] 为 null = 合并所有轨道；非 null = 仅取该原始轨道。
  /// [title]/[composer] 由调用方（转换页）传入，默认空串。
  /// [sourceMidiSha256] 由调用方传入（平台层算）；领域层不算文件 hash 但接收该值。
  DkScore generate(
    MidiData data, {
    int? melodyTrackIndex,
    String title = '',
    String composer = '',
    String sourceMidiSha256 = '',
  });
}
```

### 5.2 生成规则（Version D2）
- 选轨：`melodyTrackIndex==null` → 用 `data.notes` 全部；否则过滤 `trackIndex==melodyTrackIndex`。
- 键盘范围过滤：仅保留 `pitch` ∈ [21,108]（A0–C8）的 note；范围外丢弃（记入 warning 计数，可选）。
- **去重**：同一 `(startMs, pitch)` 的 note 合并为一个，`velocity` 取最大、`duration` 取最长。
- 输出单轨 `DkTrack(id:"main", notes: 升序)`。`hand`/`finger` 全为 null。
- `DkMeta`：title/composer/sourceMidiSha256 来自参数；`bpmBase` = tempoMap 首个 bpm 四舍五入为 int；`timeSignature`/`keySignature` 来自 data；`totalDurationMs` 来自 data。
- `tempoMap`：由 `data.tempoMap` 映射为 `DkTempoEvent` 列表。
- 产出的 `DkScore.dkVersion = "1.0"`。

### 5.3 测试（`test/domain/services/dk_generator_test.dart`）
- G1：合并模式，输入 MidiData（含 2 个同 (t,pitch) 撞键，velocity 不同）→ 去重后 1 个 note，velocity=较大值。
- G2：指定 melodyTrackIndex → 只含该轨 note。
- G3：范围外 pitch（如 10、120）被过滤。
- G4：meta 字段正确（bpmBase=tempo 首值取整、timeSignature 透传、totalDurationMs 透传）。
- G5：生成的 DkScore 经 `toJsonString`→`fromJsonString` round-trip 相等（与 Stage 2 模型联调）。
- G6：notes 升序、dkVersion=="1.0"、track.id=="main"、hand/finger 均 null。

### 5.4 禁止事项（3.2）
- 同分层禁止；禁止改 DkScore 字段契约（F-06）。
- 禁止在生成器内做自动旋律提取（Version D2 备选 B 不采纳）。
