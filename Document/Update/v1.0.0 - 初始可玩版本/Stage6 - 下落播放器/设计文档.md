## 2. 架构与数据流

```
DkScore (谱面数据)
  ↓
PlayerNotifier (状态管理)
  ├─ currentTimeMs (Ticker 驱动的播放位置)
  ├─ activeNotes (当前下落区内的 Note)
  ├─ mode (learning / performance)
  ├─ judgmentResults (判定统计)
  └─ gamePhase (playing / paused / finished)
  ↓
FallingPainter (CustomPainter)
  ├─ 每个 activeNote 根据 (t - currentTimeMs) 计算 y 坐标
  └─ 判定线渲染
  ↓
PianoPainter (CustomPainter)
  ├─ 32 键键盘（白键 37px 宽, 黑键 22px 宽）
  └─ 按键高亮（按对绿色/按错红色）
  ↓
JudgmentEngine (领域层)
  ├─ 接收 MidiInputPort.events
  ├─ 比对手动按键和当前判定窗口内的 note
  └─ 输出 JudgmentResult (perfect/early/late/miss/error)
```

## 4. 实现要点

### 4.1 PlayerNotifier (Ticker 驱动)
- 持有 `TickerProvider` → `AnimationController` 无限循环
- 每帧更新 `currentTimeMs`：`elapsed.inMilliseconds * bpmMultiplier`
- 学习模式：key 到达判定线后暂停（直到收到匹配的 MIDI noteOn）
- 演奏模式：时间持续推进，判定线不等待
- `activeNotes`：过滤 `notes.where((n) => n.t + n.d >= currentTimeMs && n.t <= currentTimeMs + fallDurationMs * 1000)`
- 演奏结束后 `gamePhase = finished`，弹出结算页

### 4.2 FallingPainter (CustomPainter)
- 计算每个 activeNote 的 y 位置：
  `y = 判定线Y - (note.t - currentTimeMs) * (下落区高 / (fallDurationSeconds * 1000))`
- 白 note 蓝 (`#60A5FA`)，黑键对应 note 紫 (`#A78BFA`)
- 长按尾巴：`height = note.d * (下落区高 / (fallDurationSeconds * 1000))`
- 判定线：一条横线 `#FCD34D`（黄色虚线）

### 4.3 PianoPainter (CustomPainter)
- 32 个白键，按 pitch 偏移滚动视口（Viewport 起始音由当前活跃 note 范围决定）
- 黑键叠在白键上，高 60% 键盘区高度
- C 键标注白线或间隔区分
- 按对→绿色高亮 200ms，按错→红色高亮 500ms

### 4.4 JudgmentEngine (领域层)
```dart
class JudgmentEngine {
  JudgmentEngine({required DkScore score, required JudgmentWidth width, required int latencyOffset});
  
  /// 处理一次用户按键
  JudgmentResult onKeyPress(int pitch, int pressTimeMs);
  
  /// 检查指定时间是否有未按的 note 已过期（仅演奏模式）
  List<MissedNote> checkMissedNotes(int currentTimeMs);
}
```
- `onKeyPress`：在 `currentTimeMs` 处寻找未判定 note（pitch 匹配，t 在窗口范围内）
  调用 `AppConfig.classify(pressTimeMs - (t + latencyOffset), width)`
- 学习模式不调用 `checkMissedNotes`；演奏模式用它统计掉 key

### 4.5 信息栏（81px 高）
曲名 | BPM | 拍号 | 调号 | 进度条 | 模式标签 | 实时统计 | 暂停按钮

### 4.6 结算页
综合得分百分比 + 完美/抢/拖/掉/错 五项明细 + "再来一次"/"返回库"
