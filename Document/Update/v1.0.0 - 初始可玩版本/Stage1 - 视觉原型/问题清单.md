### S1-1. 原型形式：md 文本 vs HTML 交互页

- **问题描述**：Stage 1 设计文档初版把"视觉原型"理解为 Markdown + ASCII + Mermaid 形式的静态线框文本。用户随后澄清需要的是**可在浏览器中打开、具备简单交互的 HTML 页面**。需要重新固化技术栈、文件组织、动画展示程度。
- **建议方案**（已与用户确认，2026-06-23）：
  - **技术栈**：Tailwind CSS（通过 CDN）+ 原生 JS，零构建步骤，浏览器双击即可查看
  - **文件组织**：单 `index.html` 主入口 + 4 个独立子页面文件（`pages/library.html` 等），主入口通过 hash 路由 + `<iframe>` 嵌入子页面以规避 `file://` CORS 问题；同时每个子页面文件自包含，可独立双击预览
  - **下落动画**：8 拍循环动画，CSS animation 或 `requestAnimationFrame`，展示真实下落节奏与触底反馈
  - **目录位置**：`Stage1 - 视觉原型/prototype/`
- **风险预警**：
  - HTML 原型用 Tailwind CDN，离线打开时需有网络拉 CDN；建议在 `prototype/README.md` 标注"需联网或使用本地 Tailwind 文件替代"
  - 子页面 iframe 嵌入对手机屏幕尺寸模拟需要在 CSS 中固定 `1920×900`（或 `2400×1080` 缩放比）以贴近真机比例，否则视觉跑偏
  - 原生 JS 没有响应式状态管理，多状态切换可能写成"显示/隐藏 div"，代码量略高于 Vue，但符合"零构建"约束
- **备选方案**（已否决）：
  - Vue 3 + Vite：需要 npm 构建，SubAgent 必须能跑 npm 命令；与"双击即开"的原型阶段定位不符
  - 纯原生 HTML/CSS/JS（无任何 CSS 框架）：CSS 代码量翻倍，影响 SubAgent 产出速度
  - 静态多状态截图：偏离用户"简单交互"明确诉求
- **用户答复**（2026-06-23）：同意建议方案
- **影响范围**：
  - 必须更新 [Version 设计文档](../设计文档.md) 第 4.3 节"Stage 1 详细范围"中关于"ASCII/Mermaid 线框"的描述
  - 必须重写 [Stage 1 设计文档](设计文档.md) 第 1.3、3.1–3.4 节
  - 必须重写 [Stage 1 验收文档](验收文档.md) 第 4 节验收项（从"目检 ASCII 比例"改为"浏览器打开 HTML 验证交互"）

## Stage 1 启动前继承的 Version 级关键决策

以下为本 Stage 必须遵守的、已在 [Version 问题清单](../问题清单.md) 关闭的决策摘要（已转写到 [Stage 1 设计文档](设计文档.md) 第 1.4 节）：

- 屏幕方向：强制横屏 2400×1080（E2）
- 键盘默认：88 键数据范围 + 32 键视口（E1）
- 信息栏：含曲名/BPM/拍号/调号/小节/进度/模式/统计，高度 ≤ 屏幕 15%（E4）
- 下落：屏高 / 1.5 秒固定速；长按 = 带尾矩形（E3）
- 学习反馈：错音闪红 + 错按键高亮 0.5s + key 停在键面上方等待（F1）
- 演奏判定：完美 ±30 / 抢 < -30 / 拖 30-80 / 掉 > 80（默认 wide 档）（C3 + F2）
