## 1. Version 目标与范围

### 1.1 目标（一句话）

构建一个**仅 Android** 的下落式钢琴学习 App，用户可：导入 MIDI 文件 → 生成 DK 谱 → 横屏下落播放 → 通过 USB OTG 连接电钢琴弹奏 → 学习模式逐 key 等待 / 演奏模式按时间线推进并统计 → 本地导入导出 DK 谱。

### 1.2 In Scope

| 范围项 | 说明 |
|---|---|
| 平台构建产物 | Android（仅 Android），最小 API 24（Android 7.0），目标 API = 最新稳定版 |
| 跨平台代码组织 | 使用 Flutter 单代码库 + 严格三层分层，**领域层必须 100% 平台无关**以备 iOS/Windows 移植 |
| MIDI 文件支持 | Standard MIDI File (SMF) 格式 0 与格式 1，单字节编码 |
| MIDI 实时输入 | 仅 USB OTG（USB MIDI Class Compliant），不支持蓝牙/Wi-Fi MIDI |
| 模式 | 学习模式（等待用户按对）、演奏模式（按 MIDI 时间线推进 + 统计） |
| 判定窗口 | 默认 ±80ms（完美 ±30ms，抢拍 < -30ms，拖拍 30-80ms，掉 key > 80ms） |
| BPM 调节 | 倍率 0.5x-2.0x，步进 0.05x |
| DK 谱格式 | `.dk.json`，UTF-8 JSON，含 `dkVersion` 顶层字段 |
| 屏幕 | 强制横屏，目标分辨率 2400×1080 |
| 键盘 | 88 键全数据范围，UI 默认 32 键滚动视口（24/32/40 可选） |
| 谱面管理 | 本地 App 私有目录 + SAF 导入导出 |

### 1.3 Out of Scope（v1.0.0 明确不做）

| 项 | 留到 |
|---|---|
| iOS / Windows 构建产物 | v2.0.0 |
| 蓝牙 MIDI / Wi-Fi MIDI | 后续版本 |
| 云账号、谱面市场、社区 | 后续版本 |
| 手位识别（左手/右手 + 指法） | v1.1.0 |
| 长按时长判定 / 延音踏板判定 | v1.1.0 |
| 自动旋律提取 | 后续版本 |
| 折叠屏 / 平板适配 | 后续版本 |
| App 内置 SoundFont 合成（声音来源仅靠电钢琴本身） | 永不（架构上排除） |
| 后端服务（网络） | v2.0.0+ |

## 2. 整体架构

### 2.1 三层架构

```
┌────────────────────────────────────────────────────┐
│  UI 层（Flutter Widget + CustomPainter + Ticker）   │

                     ↓ 调用领域层接口

│  领域层（纯 Dart，零平台依赖）                       │
│  - 模型：DkScore / DkNote / DkMeta / DkTempoMap     │
│  - 服务：MidiParser / DkGenerator / JudgmentEngine /│
│         StatisticsAggregator / BpmScaler             │
│  - 配置：AppConfigSchema                             │
│  - 异常：DkException 体系                            │
└────────────────────────────────────────────────────┘
                     ↓ 调用平台层接口（抽象）
┌────────────────────────────────────────────────────┐
│  平台层（Platform Adapter，平台特定实现）            │
│  - PlatformMidiInput（Android: MidiManager + Kotlin）│
```

### 2.2 分层强制约束

> **每个 SubStage 的开发都必须遵守，违反即视为任务失败。**

| 约束 | 适用范围 | 检查方式 |
|---|---|---|
| 领域层禁止 import 任何平台 SDK | `lib/domain/**` | 静态检查脚本：grep import 路径黑名单 |
| 领域层禁止 import `dart:io` 之外的 IO 操作 | `lib/domain/**` | 同上 |
| 平台层接口必须先在领域层定义 abstract class，再在 platform 层实现 | `lib/domain/ports/*` + `lib/platform/*` | 代码 review |
| UI 层禁止直接 import 平台层实现，必须通过领域层接口 | `lib/ui/**` | 同上 |
| 所有平台通道命名空间统一前缀 `keydrop_piano/` | `lib/platform/**` | 同上 |
| 状态管理仅允许 `flutter_riverpod` | `pubspec.yaml` + UI 层 | 依赖检查 |

## 3. 跨 Stage 接口契约（强制）

> **以下接口在 Stage 2 完成定义，所有后续 Stage 必须严格遵守。任何 SubAgent 不得擅自修改字段、类型、命名。**

### 3.1 DK 谱模型（领域层）

```dart
// lib/domain/models/dk_score.dart
class DkScore {
  final String dkVersion;          // 形如 "1.0"
  final DkMeta meta;
  final List<DkTrack> tracks;
  final List<DkTempoEvent> tempoMap;
}

class DkMeta {
  final String title;
  final String composer;
  final String sourceMidiSha256;   // 源 MIDI 文件 sha256，用于追溯
  final int bpmBase;               // 谱面基础 BPM
  final String timeSignature;      // "4/4"
  final String keySignature;       // "C"
  final int totalDurationMs;
}

class DkTrack {
  final String id;                 // v1.0.0 固定为 "main"
  final List<DkNote> notes;        // 按 t 升序
}

class DkNote {
  final int t;                     // 起始毫秒（相对曲首）
  final int d;                     // 持续毫秒
  final int pitch;                 // MIDI 音高 0-127
  final int velocity;              // 0-127
  final String? hand;              // v1.0.0 为 null
  final int? finger;               // v1.0.0 为 null
}

class DkTempoEvent {
  final int t;                     // 毫秒
  final double bpm;                // 该时刻起的瞬时 BPM
}
```

**序列化规则**：
- 顶层字段名严格如上（大小写敏感，camelCase）。
- 时间统一毫秒整数，禁止使用 float。
- `notes` 列表必须按 `t` 升序，反序列化时若发现乱序需主动排序并 warning。
- 反序列化时若 `dkVersion > 1.0` → 抛 `DkVersionTooHighException`；若 `< 1.0` → 调用升级器（v1.0.0 占位实现，仅打印 warning 后直接当作 1.0 处理）。
- JSON 编码使用 `dart:convert` 默认 + `const JsonEncoder.withIndent('  ')` 输出 indented JSON 便于人类调试。

### 3.2 配置项 Schema（领域层）

```dart
// lib/domain/models/app_config.dart
class AppConfig {
  final int hardwareKeyboardKeys;        // 49 | 61 | 76 | 88
  final int viewportKeys;                 // 24 | 32 | 40
  final ScrollMode scrollMode;            // auto | manual | fixed
  final double fallDurationSeconds;       // 1.0 ~ 3.0
  final JudgmentWidth judgmentWidth;      // strict (60ms) | medium (100ms) | wide (160ms)
  final int inputLatencyOffsetMs;         // -100 ~ +100
  final double bpmMultiplier;             // 0.5 ~ 2.0
  final PlayMode defaultMode;             // learning | performance
}

enum ScrollMode { auto, manual, fixed }
enum JudgmentWidth { strict, medium, wide }
enum PlayMode { learning, performance }
```

**判定窗口语义**（基于 JudgmentWidth + 全局延迟补偿）：

| 档位 | 完美窗 | 抢拍窗 | 拖拍窗 | 掉 key 阈 |
|---|---|---|---|---|
| strict | ±15ms | < -15ms 到 -30ms | 15-30ms | > 30ms |
| medium | ±25ms | < -25ms 到 -50ms | 25-50ms | > 50ms |
| wide（默认） | ±30ms | < -30ms 到 -80ms | 30-80ms | > 80ms |

所有时间均按 `按下时刻 - (key 触底时刻 + inputLatencyOffsetMs)` 计算。

### 3.3 MIDI 输入端口（领域层 → 平台层）

```dart
// lib/domain/ports/midi_input_port.dart
abstract class MidiInputPort {
  /// 当前已连接设备名（可能为 null = 无连接）
  Stream<String?> get connectedDeviceName;

  /// 实时 MIDI 事件流
  Stream<MidiEvent> get events;

  /// 主动扫描并尝试连接首个 USB MIDI 设备
  Future<void> tryConnect();

  /// 断开当前设备
  Future<void> disconnect();
}

class MidiEvent {
  final MidiEventType type;        // noteOn | noteOff | controlChange | other
  final int channel;               // 0-15
  final int pitch;                 // 仅 noteOn/noteOff 有效
  final int velocity;              // 仅 noteOn/noteOff 有效
  final int controllerNumber;      // 仅 controlChange 有效
  final int controllerValue;       // 仅 controlChange 有效
  final int timestampUs;           // 平台时间戳（微秒），用于延迟分析
}
```

### 3.4 文件系统端口（领域层 → 平台层）

```dart
// lib/domain/ports/file_system_port.dart
abstract class FileSystemPort {
  /// 列出 App 私有目录下的所有 .dk.json 文件
  Future<List<DkScoreFile>> listDkScores();

  /// 读取指定 .dk.json 文件内容
  Future<String> readDkScore(String fileId);

  /// 写入 .dk.json 文件到 App 私有目录
  Future<String> writeDkScore(String fileName, String content);

  /// 删除指定文件
  Future<void> deleteDkScore(String fileId);

  /// 重命名指定文件
  Future<void> renameDkScore(String fileId, String newName);

  /// 通过 SAF 选择外部 MIDI 文件，返回临时复制路径
  Future<String?> pickMidiFile();

  /// 通过 SAF 将指定 .dk.json 导出到用户选定位置
  Future<bool> exportDkScore(String fileId);
}

class DkScoreFile {
  final String fileId;             // 内部 ID（即文件名 hash 或路径）
  final String displayName;        // 用户可见名称
  final int sizeBytes;
  final DateTime modifiedAt;
}
```

### 3.5 异常体系

```dart
// lib/domain/exceptions/dk_exception.dart
sealed class DkException implements Exception { String get message; }

class UnsupportedMidiFormatException extends DkException { ... }   // 格式 2 / SysEx 中含格式 2 标志等
class CorruptedMidiException extends DkException { ... }
class DkVersionTooHighException extends DkException { ... }
class MidiDeviceConnectionException extends DkException { ... }
class FileSystemException extends DkException { ... }
```

**UI 层处理规则**：捕获到任一 DkException → 弹 AlertDialog 显示 `e.message` + "请检查文件 / 设备" 提示，不崩溃。

## 4. Stage 拆分方案

### 4.1 Stage 依赖图

```
Stage 1 (视觉原型) ──┐
                    ├──> Stage 2 (Flutter 骨架 + 领域层基础)
                    │       │
                    │       ├──> Stage 3 (MIDI 解析 + DK 谱生成)
                    │       │           │
                    │       ├──> Stage 4 (Android MIDI 平台层 + Test Hook + 文件系统)
                    │       │           │
                    │       │           └────┐
                    │       │                │
                    │       └────────────────┼──> Stage 5 (UI: 谱面库 + 设置 + 转换页)
                    │                        │           │
                    │                        │           └──> Stage 6 (UI: 下落播放器 + 判定 + 统计)
                    │                        │                       │
                    │                        │                       └──> Stage 7 (集成 + 真机验收 + 总结)
```

**说明**：
- Stage 1 与 Stage 2 不直接代码依赖，但 Stage 2 在 Stage 1 用户视觉确认通过后才开工（避免架构与最终 UI 错位）。
- Stage 3 与 Stage 4 之间无直接代码依赖，**理论上可并行**，但因 SubAgent 数量受限，建议串行执行 Stage 3 → Stage 4。
- Stage 5 必须等 Stage 3 + Stage 4 都完成（库需要文件系统，转换页需要 MIDI 解析）。

### 4.8 Stage 6 范围

**目标**：UI 层实现下落式播放器，含学习/演奏双模式与判定。

**SubStage**：
- 6.1: `PianoKeyboardPainter` + `FallingNotePainter`（CustomPainter + Ticker）+ 性能验证（≥ 55fps on 小米17 Ultra）

### 4.9 Stage 7 范围

**目标**：集成、自动化测试（含 Test Hook 注入伪 MIDI 的端到端测试）、真机抽样验收、Version 总结报告。

| App 内置发声 | 完全无，仅依赖电钢琴本身 | F1 |
| 长按判定 | v1.0.0 仅判按下时刻 | F5 |

## 7. 全 Version 禁止事项汇总

| 编号 | 禁止 | 检查方式 |
|---|---|---|
| F-01 | 领域层 import 平台 SDK | 静态脚本 |

| F-03 | 网络请求 | 代码 review + Android Manifest 不申请 INTERNET 权限 |
| F-04 | 直接使用 Widget 动画做下落 key | 代码 review |
| F-05 | 在主线程做 MIDI 文件解析（必须 isolate 或 compute） | 代码 review + 性能测试 |
| F-06 | 修改 DK 谱顶层字段名 / 类型 | 代码 review + JSON Schema 测试 |
| F-07 | SubAgent 跨 SubStage 沟通 | MainAgent 监督 |
| F-08 | 把无法执行的硬件验收项默认为通过 | 验收文档强制门禁 |
