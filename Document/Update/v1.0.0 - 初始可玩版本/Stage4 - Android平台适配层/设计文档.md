## 4. SubStage 任务书

### 4.1 Kotlin MidiInputPlugin

**通道名**（Version 强制前缀 `keydrop_piano/`）：
- EventChannel（MIDI 事件流）：`keydrop_piano/midi_events`
- EventChannel（设备名变化）：`keydrop_piano/midi_device`
- MethodChannel（控制）：`keydrop_piano/midi_control`
  - `tryConnect` → 扫描首个 USB MIDI 设备并打开 input port
  - `disconnect` → 关闭当前设备

**实现要点**：
- 使用 `android.media.midi.MidiManager.openDevice(info, onDeviceOpened, handler)` 扫描设备
- `MidiDeviceInfo` 列表用 `MidiManager.getDevices()` 获取
- 打开设备后 `MidiDevice.openInputPort(index)` 得到 `MidiInputPort`，`connect(MidiReceiver)` 注册回调
- 回调中 `MidiReceiver.onSend(msg, offset, count, timestamp)` → 将原始 MIDI 字节数组通过 `EventChannel.StreamHandler.onListen` 的 `EventSink.success(bytes)` 推向 Dart 端
- `timestamp` 使用 `System.nanoTime()` 转换微秒
- 设备插拔监听：`MidiManager.registerDeviceCallback(MidiManager.DeviceCallback{onDeviceAdded/Removed})`，更新设备名流
- MainActivity 中在 `configureFlutterEngine` 里注册 `MidiInputPlugin` 为 `FlutterPlugin`

**AndroidManifest 修改**（在 `</application>` 前或根增加）：
```xml
<uses-feature android:name="android.hardware.usb.host" android:required="false"/>
<uses-feature android:name="android.software.midi" android:required="false"/>
```
（required=false 因 App 可无电钢琴运行，Play Store 不过滤）

### 4.2 Dart AndroidMidiInputAdapter

**文件**：`lib/platform/android/android_midi_input_adapter.dart`

**实现** `MidiInputPort`（Stage 2 端口）：
- 构造时初始化 EventChannel 与 MethodChannel
- `connectedDeviceName`：监听 `keydrop_piano/midi_device` EventChannel 的 `List<int>?` → 解码为 UTF-8 String?；无设备时发送 null
- `events`：监听 `keydrop_piano/midi_events` EventChannel，收到 `List<int>` → 解析为 `MidiEvent`（解析 3 字节 MIDI 消息：statusByte→type+channel, data1, data2。注：v1.0.0 适配器解析原始 MIDI 字节，不做完整 SMF 处理（不含 SysEx、running status — 底层驱动通常已拆分））
- 事件队列：内部 `StreamController<MidiEvent>.broadcast()` 作为事件源；EventChannel 收到数据后 push 到 controller
- `tryConnect` → MethodChannel `invokeMethod('tryConnect')`
- `disconnect` → MethodChannel `invokeMethod('disconnect')`

**MIDI 字节→MidiEvent 解析**（简易，与 Kotlin 端约定）：
- Kotlin 端每条 MIDI 消息作为 4 字节打包发送：`[status, data1, data2, timestamp_4bytes_little_endian]`？不，简化：Kotlin 端直接用 `int` status + `int` data1 + `int` data2 + `long` timestampUs 打包为 `ByteBuffer`。约定格式：每包 14 字节（status(4B LE) + channel(4B LE) + data1(2B LE) + data2(2B LE) + timestampUs(8B LE)→等等，用可扩展格式。最简单：直接在 Kotlin 端发 `ByteArray` 编码序列：`[status, data1, data2]` 后接 8 字节 timestampUs（大端）。共 11 字节固定包。
- 更简单：在 Kotlin 端直接把完整的 `MidiMessage` 转换为 int 数组编码。但 `EventChannel` 通常发 `ByteBuffer`。约定：每条 MIDI 消息 11 字节：
  - byte 0: status (0x80..0xBF 或 0xF0..0xFF)
  - byte 1: data1 (pitch / controller number)
  - byte 2: data2 (velocity / controller value)
  - bytes 3-10: timestamp 微秒（long，大端）
  实际上 EventChannel 推送字节数组，Dart 端按 11 字节切分。但现实中 `android.media.midi` 的 `onSend` 给你的是原始 MIDI 字节（可能是多个消息打包，也可能单个）。Kotlin 端按**完整 MIDI 消息**逐个发送：每发一条消息，附加 8 字节 timestamp。
- **约定采纳**：Kotlin 端在 `onSend` 回调中遍历 `msg[offset..offset+count]` 按 MIDI 状态字节拆分为单条消息；对每条消息，打包 `[status, data1, data2, timestamp8B_BE]` 写入 `ByteBuffer`，通过 `EventSink.success(buffer)` 发送。Dart 适配器接收 `Uint8List`，按 11 字节切分，还原 `MidiEvent`。

### 4.3 DebugMidiInjector

**文件**：`lib/platform/debug/debug_midi_injector.dart`

**目的**：Stage 7 集成测试 / 无电钢琴时演示。仅 debug 模式构建。

- 公开方法 `Future<void> inject(MidiEvent event)`，将 event 写入内部 `StreamController`（与 `AndroidMidiInputAdapter` 共享同一个事件流）
- 不依赖 `dart:io` / 平台 API；纯 Dart，仅通过 `kDebugMode` 或 `assert((){...})` 在 debug 模式注入
- 在 `di/providers.dart` 中条件注册：debug 模式下用注入器包装 `MidiInputPort`，release 模式仅用真实适配器
- 简单实现：`DebugMidiInjector` 持有一个 `StreamController<MidiEvent>.broadcast()` 作为事件源，其 `events` getter 返回 stream

### 4.4 FileSystemPlugin + Adapter + ConfigRepo

**Kotlin**: `FileSystemPlugin.kt`，MethodChannel `keydrop_piano/file_system`：
- 私有目录：`context.getExternalFilesDir(null).absolutePath`
- `listDkScores` → 遍历目录，返回 JSON 数组 `[{fileId, displayName, sizeBytes, modifiedAt}]`
- `readDkScore(fileId)` → 读取文件内容为 String
- `writeDkScore(fileName, content)` → 写入 .dk.json，返回 fileId
- `deleteDkScore(fileId)` → 删除文件
- `renameDkScore(fileId, newName)` → 重命名
- `pickMidiFile` → 通过 `ActivityResultContracts.OpenDocument` 选择 "audio/midi", "audio/x-midi" 类型，复制到临时目录返回路径
- `exportDkScore(fileId)` → 通过 `ActivityResultContracts.CreateDocument` 导出

**Dart**: `android_file_system_adapter.dart`（实现 `FileSystemPort`）：
- 私有目录路径由 Kotlin 侧提供（首次调用时获取，缓存）
- `pickMidiFile` 与 `exportDkScore` 通过 `MethodChannel` `invokeMethod` 触发 Kotlin 端 SAF；Kotlin 端在 `onMethodCall` 中启动 ActivityContract，完成后在 contract 回调中通过 `Result.success/error` 返回

**Dart**: `android_config_repository.dart`（实现 `ConfigRepositoryPort`）：
- `load()` → `SharedPreferences.getInstance().getString('app_config')` → `AppConfig.fromJson`（无记录返回 defaults）
- `save(AppConfig)` → `SharedPreferences.getInstance().setString('app_config', jsonEncode(config.toJson()))`
