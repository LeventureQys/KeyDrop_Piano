## 1. Stage 目标与背景

### 1.1 目标（1 句话）

建立 `app/` Flutter 工程骨架，实现**领域层全部基础契约**（DK 谱模型 + JSON 序列化、AppConfig 配置、异常体系、平台端口 abstract class），并建立分层强制约束的自检脚本；交付物满足 `flutter analyze` 0 警告、`flutter test` 全绿、分层检查通过。

### 1.2 背景

- 仓库当前**无任何 Flutter 代码**（无 `app/` 目录）。
- Version 设计文档第 3 节已**完整定义**跨 Stage 接口契约（DkScore/DkMeta/DkTrack/DkNote/DkTempoEvent、AppConfig + 枚举、MidiInputPort + MidiEvent、FileSystemPort + DkScoreFile、DkException 体系）。Stage 2 = 将这些契约落地为 Dart 代码 + 测试。

## 4. SubStage 任务书

### 4.1 SubStage 2.1 - 工程骨架 + 分层自检

#### 背景与目标
建立可编译运行的 Flutter 工程骨架，集成 Riverpod，建立 lint 与分层约束自检脚本。本 SubStage **不实现任何业务模型**，仅保证 `flutter analyze` 0 警告、`flutter test`（空测试或 smoke 测试）通过、分层脚本可运行。

#### 操作步骤
1. 在仓库根执行 `flutter create --org com.keydrop --project-name keydrop_piano --platforms=android app`。
2. `cd app`，执行 `flutter pub add flutter_riverpod shared_preferences`。
3. 删除 `flutter create` 生成的示例 `test/widget_test.dart` 中对默认计数器的断言，替换为一个最小 smoke 测试（仅验证 `MyApp`/`KeyDropApp` 可构建）。
4. 改写 `lib/main.dart`：用 `ProviderScope` 包裹 `runApp`；调用 `WidgetsFlutterBinding.ensureInitialized()`。横屏锁定与屏幕常亮在本 Stage **仅留 TODO 注释占位**（实际逻辑在 Stage 6，避免引入平台依赖）。
5. 新建 `lib/app.dart`：`KeyDropApp extends StatelessWidget`，返回 `MaterialApp`，`home` 为一个占位 `Scaffold`（显示 "KeyDrop Piano"）。
6. 新建 `lib/di/providers.dart`：空文件 + 文件级注释，作为后续 Provider 集中注册点。
7. 新建 `lib/domain/`、`lib/platform/`、`lib/ui/` 三个目录，各放一个 `.gitkeep` 或占位 `barrel` 注释文件，确保目录存在。
8. 配置 `analysis_options.yaml`：`include: package:flutter_lints/flutter.yaml`，并启用以下额外规则（见 4.1 lint 清单）。
9. 新建 `tool/check_layering.dart`（纯 Dart 脚本，详见下文），可用 `dart run tool/check_layering.dart` 执行。

#### `analysis_options.yaml` 必含规则
```yaml
include: package:flutter_lints/flutter.yaml
linter:
  rules:
    - prefer_const_constructors
    - prefer_final_locals
    - avoid_print          # 领域层禁止 print；脚本/调试需用 debugPrint 或显式 ignore
    - always_declare_return_types
analyzer:
  language:
    strict-casts: true
    strict-raw-types: true
  errors:
    invalid_annotation_target: ignore
```

#### `tool/check_layering.dart` 行为契约（强制）
纯 Dart 脚本，扫描 `lib/domain/` 下所有 `.dart` 文件，检测**禁止的 import**，违反则以**非 0 退出码**结束并打印违规文件 + 行号。规则：

- 黑名单 import 前缀（领域层禁止）：
  - `package:flutter/`（含 material/widgets/cupertino 等所有 Flutter UI）
  - `dart:io`
  - `dart:ui`
  - `package:shared_preferences/`
  - 任意 `../platform/` 或 `package:keydrop_piano/platform/` 路径
- 允许：`dart:convert`、`dart:math`、`dart:typed_data`、`package:meta/`、领域层内部相对 import。
- 输出格式（每条违规一行）：`LAYERING VIOLATION: <相对路径>:<行号>: <被禁import>`。
- 无违规时打印 `LAYERING OK: scanned <N> files in lib/domain` 并 `exit(0)`。

> 该脚本是 Version 设计文档 2.2 节"领域层禁止 import 平台 SDK"约束的执行器，后续每个 Stage 的验收都会调用它。

#### 完成判定
- [ ] `app/` 工程存在，`flutter pub get` 成功。
- [ ] `flutter analyze` 输出 `No issues found!`（0 warning / 0 error）。
- [ ] `flutter test` 全绿（至少 smoke 测试通过）。
- [ ] `dart run tool/check_layering.dart` 运行成功（此时 `lib/domain/` 可能为空或仅占位，应输出 `LAYERING OK`）。

#### 禁止事项
- 禁止在 `pubspec.yaml` 引入音频合成 / 网络包。
- 禁止启用 web / ios / windows / linux / macos 平台（仅 android）。
- 禁止在 `lib/domain/` 写任何业务逻辑（属于 2.2/2.3）。

### 4.2 SubStage 2.2 - DK 谱模型 + JSON 序列化

#### 背景与目标
在领域层实现 DK 谱数据模型与 JSON 双向序列化，**纯 Dart，零平台依赖**。模型字段与序列化规则**严格遵守 Version 设计文档 3.1 节**，不得增删改字段名 / 类型。

#### 输入
- [Version 设计文档 3.1 节 DK 谱模型](../设计文档.md) + 3.5 节异常体系（依赖 2.3 的 `DkVersionTooHighException`，见跨 SubStage 契约说明）。

#### 必须实现的类（`lib/domain/models/dk_score.dart`）
严格按 Version 设计文档 3.1：`DkScore`、`DkMeta`、`DkTrack`、`DkNote`、`DkTempoEvent`。要求：
- 全部 `@immutable`，字段 `final`，提供 `const` 构造（`DkNote` 可 const）。
- 每个类提供：
  - 命名构造 `fromJson(Map<String, dynamic> json)`。
  - 方法 `Map<String, dynamic> toJson()`。
- `DkScore` 额外提供：
  - `factory DkScore.fromJsonString(String s)`：内部 `jsonDecode` 后调用 `fromJson`。
  - `String toJsonString()`：用 `const JsonEncoder.withIndent('  ')` 输出 indented JSON。

#### 序列化规则（强制，对应 Version 3.1）
1. 顶层与嵌套字段名严格 camelCase，大小写敏感：`dkVersion`、`meta`、`tracks`、`tempoMap`、`title`、`composer`、`sourceMidiSha256`、`bpmBase`、`timeSignature`、`keySignature`、`totalDurationMs`、`id`、`notes`、`t`、`d`、`pitch`、`velocity`、`hand`、`finger`、`bpm`。
2. 时间字段（`t`、`d`、`totalDurationMs`）一律 `int`（毫秒），禁止 float。`DkTempoEvent.bpm` 为 `double`。
3. `DkTrack.notes` 反序列化后**必须按 `t` 升序排序**；若输入乱序，排序并通过 `debugPrint`（或返回 warning 标志）记录。本 Stage 用一个可选的 `void Function(String)? onWarning` 注入点，默认 `null`（不打印），便于测试断言。
4. 反序列化版本校验（`DkScore.fromJson`）：
   - 解析 `dkVersion` 为形如 `"major.minor"`。
   - 若 `major > 1`（即 > "1.x"）→ 抛 `DkVersionTooHighException`（来自 2.3）。
   - 若 `major == 1 && minor < 0`（不可能）忽略；`< "1.0"` 的情况：调用占位升级器 = 仅 `onWarning?.call(...)` 后按 1.0 处理。
   - 合法范围：`dkVersion` 主版本 == 1。
5. `hand`、`finger` 为可空（`String?` / `int?`）；序列化时若为 null **仍写出** `"hand": null`（保证 round-trip 稳定）。

#### 必须的单元测试（`test/domain/models/dk_score_test.dart`，覆盖率目标 ≥ 90%）
- T1 round-trip：构造一个含 2 轨、每轨 3 note、2 个 tempo 事件的 `DkScore` → `toJsonString` → `fromJsonString` → 字段逐一相等。
- T2 字段名校验：`toJson()` 的 key 集合精确等于规范字段集合（断言无多余/缺失 key）。
- T3 notes 乱序自动排序：传入 `t` 乱序的 notes，`fromJson` 后 `notes` 按 `t` 升序，且 `onWarning` 被调用一次。
- T4 时间类型：断言 `t/d/totalDurationMs` 反序列化为 `int`；`bpm` 为 `double`。
- T5 版本过高：`dkVersion: "2.0"` → `expect(() => DkScore.fromJsonString(...), throwsA(isA<DkVersionTooHighException>()))`。
- T6 版本过低占位升级：`dkVersion: "0.9"` → 不抛异常，`onWarning` 被调用。
- T7 null 字段 round-trip：`hand`/`finger` 为 null 时 round-trip 后仍为 null 且 JSON 含 `"hand": null`。

#### 完成判定
- [ ] 文件存在，`flutter analyze` 0 警告。
- [ ] `flutter test test/domain/models/dk_score_test.dart` 全绿。
- [ ] `dart run tool/check_layering.dart` 仍 `LAYERING OK`（dk_score.dart 不得 import Flutter / dart:io）。

#### 禁止事项
- 禁止 import `package:flutter/*`、`dart:io`、`dart:ui`、平台层。
- 禁止改动 Version 3.1 字段名 / 类型（Version 禁止事项 F-06）。
- 禁止把版本异常类定义在本文件（异常体系属 2.3，本文件 import 之）。

#### 跨 SubStage 契约说明
- 本文件 `import '../exceptions/dk_exception.dart';` 使用 `DkVersionTooHighException`。该异常由 SubStage 2.3 定义。集成时 2.3 必须先合入或与本文件一并合入。MainAgent 负责合并顺序。

### 4.3 SubStage 2.3 - 配置 + 异常 + 端口

#### 背景与目标
实现领域层 `AppConfig` 配置模型（含默认值与判定窗口语义）、`DkException` sealed 异常体系、三个平台端口 abstract class（MIDI 输入 / 文件系统 / 配置持久化）。**纯 Dart，零平台依赖**（端口仅定义 abstract class，不含实现）。

#### 输入
- [Version 设计文档 3.2 节 AppConfig + 判定窗口表](../设计文档.md)、3.3 节 MidiInputPort、3.4 节 FileSystemPort、3.5 节异常体系。

#### 4.3.1 `lib/domain/exceptions/dk_exception.dart`
严格按 Version 3.5：
```dart
sealed class DkException implements Exception {
  String get message;
}
```
子类（每个含 `final String message;` 构造，`toString()` 返回 `'<RuntimeType>: $message'`）：
- `UnsupportedMidiFormatException`
- `CorruptedMidiException`
- `DkVersionTooHighException`
- `MidiDeviceConnectionException`
- `FileSystemAccessException`（注：Version 3.5 写作 `FileSystemException`，但 Dart `dart:io` 已有同名类，为避免歧义与误导入，**本项目统一命名 `FileSystemAccessException`**；这是对 Version 3.5 的命名细化，语义不变。）

#### 4.3.2 `lib/domain/models/app_config.dart`
严格按 Version 3.2：`AppConfig`（`@immutable`，全 `final`，`const` 构造）+ 枚举 `ScrollMode`/`JudgmentWidth`/`PlayMode`。要求：
- 字段：`hardwareKeyboardKeys`(int 49|61|76|88)、`viewportKeys`(int 24|32|40)、`scrollMode`、`fallDurationSeconds`(double 1.0~3.0)、`judgmentWidth`、`inputLatencyOffsetMs`(int -100~+100)、`bpmMultiplier`(double 0.5~2.0)、`defaultMode`。
- `enableDebugMidiInjector`(bool，默认 false)：原型设置页含"调试 DebugMidiInjector 开关"，故配置需承载该字段（对应 Stage 4 DebugMidiInjector / 原型 SET 调试分组）。
- 默认值常量 `static const AppConfig defaults`：
  - `hardwareKeyboardKeys = 88`、`viewportKeys = 32`、`scrollMode = ScrollMode.auto`、`fallDurationSeconds = 1.5`、`judgmentWidth = JudgmentWidth.wide`、`inputLatencyOffsetMs = 0`、`bpmMultiplier = 1.0`、`defaultMode = PlayMode.learning`、`enableDebugMidiInjector = false`。（来源：Version 决策表）
- `AppConfig copyWith({...})`：所有字段可选覆盖。
- `Map<String,dynamic> toJson()` / `factory AppConfig.fromJson(Map<String,dynamic>)`：枚举以其 `name` 字符串序列化；反序列化未知值回退默认值并不抛异常。
- 判定窗口计算（Version 3.2 表）：提供
  ```dart
  class JudgmentWindow {
    final int perfectMs;   // 完美窗 ± 值
    final int lateMaxMs;   // 拖拍上限（掉 key 阈）
    const JudgmentWindow(this.perfectMs, this.lateMaxMs);
  }
  JudgmentWindow windowFor(JudgmentWidth w);
  ```
  映射：strict → (15, 30)；medium → (25, 50)；wide → (30, 80)。
  - 判定语义（供 Stage 6 使用，本 Stage 仅实现 `windowFor` + 一个纯函数 `JudgmentResult classify(int deltaMs, JudgmentWidth w)`）：
    - `deltaMs = 按下时刻 - (触底时刻 + inputLatencyOffsetMs)`（本函数入参已是补偿后的 delta）。
    - `|delta| <= perfectMs` → perfect
    - `delta < -perfectMs`（且在窗口内，即 `delta >= -lateMaxMs`）→ early（抢拍）
    - `perfectMs < delta <= lateMaxMs` → late（拖拍）
    - `delta > lateMaxMs` 或 `delta < -lateMaxMs` → miss（掉 key / 超窗）
  - `enum JudgmentResult { perfect, early, late, miss }`

#### 4.3.3 `lib/domain/ports/midi_input_port.dart`
